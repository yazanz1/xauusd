## 3. הלוגיקה של כל פילטר

### H1 — `h1_ema_side` (קיים בקוד, רץ ב־shadow)
- **הנר:** נר ה־H1 האחרון **שנסגר לפני** השעה של נר האיתות. לדוגמה, איתות ב־14:35 משתמש בנר 13:00–14:00.
- **הנתונים:** `copy_rates_from_pos(symbol, TIMEFRAME_H1, pos=1+hours_since, 600)` מהברוקר. `hours_since` הוא מספר השעות השלמות שעברו מאז שעת האיתות.
- **EMA50:** ממוצע פשוט של 50 הסגירות הראשונות כנקודת התחלה, ואחר כך `ema = close×2/51 + ema×49/51`.
- **חסימה:**
  - לונג נחסם אם `close_H1 ≥ EMA50`, כלומר לונג מותר רק מתחת ל־EMA.
  - שורט נחסם אם `close_H1 ≤ EMA50`, כלומר שורט מותר רק מעל.
- **Env:** ‏`H1_EMA_MODE`. הערכים: `shadow` (ברירת מחדל), `block`, `off`. השם שונה מ־`FILTER_*`, כי כך הוא כבר כתוב בקוד.
- **Fail-open:** אם חסרים נתונים או יש שגיאה, הפילטר מאשר את העסקה.
- **המלצה:** `H1_EMA_MODE=block`. על 954 העסקאות האמיתיות, אלה שהיו נחסמות הסתכמו ב־‎−$4,769 (סעיף 8).

### E — `ny_midday` (חדש) — צהרי ניו יורק
- **השעה:** זמן האיתות (`created_at`, ראה 9.3) מומר לשעון `America/New_York`.
- **חסימה:** אם השעה בטווח `[12:00, 14:00)`. ‏12:00:00 נחסם, ‏14:00:00 מותר.
- כל הצבעים וכל הימים.
- **לא צריך MT5.** רק `zoneinfo`. רץ מוקדם בשרשרת.
- **Env:** ‏`FILTER_NY_MIDDAY_MODE`, ‏`NY_MIDDAY_START=12:00`, ‏`NY_MIDDAY_END=14:00`.
- **הסבר:** אלה שעות הצהריים של ניו יורק, עם נזילות נמוכה והרבה פריצות שווא. על העסקאות האמיתיות: 93 עסקאות, ‎−$1,942, ‏45% מרוויחות, ושלילי בשני חצאי התקופה.

### F — `one_per_bar` (חדש) — עסקה אחת לכל נר
- **המפתח:** `(entry_time, direction)` של האיתות.
- **חסימה:** אם כבר קיימת שורה אחרת ב־`gold_trades` עם אותו `entry_time`, אותו `direction`, ו־`mt5_ticket IS NOT NULL` (כלומר כבר נפתחה ב־MT5).
- **סדר העדיפות:** מי שנתפס ראשון ב־`claim_signal` נפתח. לכן בפועל זה לפי סדר `created_at`.
- **צבעים:** כל הצבעים נחשבים, כלומר צהוב + NY או צהוב + לונדון באותו נר ובאותו כיוון. כיוון הפוך באותו נר לא נחסם.
- **הנתונים:** הפילטר לא פונה ל־Supabase בעצמו. `bot.py` מעביר `context["same_bar_open"]` (סעיף 4.3).
- **Env:** ‏`FILTER_ONE_PER_BAR_MODE`.
- **הסבר:** אותה פריצה נכנסת פעמיים, והסיכון כפול. על העסקאות האמיתיות: 132 עסקאות כפולות, ‎−$1,586.

### G — `min_rr` (חדש, לשקול) — יעד קרוב מהסטופ
- `risk = |entry − stop|`, ‏`reward = |tp − entry|`. שלושתם מהשורה של ה־webhook (מחירי Pine).
- **חסימה:** אם `reward / risk < MIN_RR`. ברירת המחדל: `1.0`.
- **לא צריך MT5.**
- **Env:** ‏`FILTER_MIN_RR_MODE` (ברירת מחדל `off`), ‏`MIN_RR=1.0`.
- **הסבר:** 203 עסקאות, ‎−$1,910, למרות 66% מרוויחות, כי הרווח הממוצע $47 וההפסד הממוצע $120. אבל הפילטר לא משפר כשמוסיפים אותו ל־H1 + E + F, ולכן ברירת המחדל היא `off`.

## 4. ארכיטקטורת קוד

```
filters/
  __init__.py          ← active_filters(): להוסיף E, F, G (סדר בסעיף 4.4)
  _mode.py             ← חדש: shadow / block / off משותף
  ny_midday.py         ← E
  one_per_bar.py       ← F
  min_rr.py            ← G
  h1_ema_side.py       ← קיים (רק לשנות mode ב־.env)
```

### 4.1 `filters/_mode.py` (חדש)
```python
def mode(env_name: str, default: str = "shadow") -> str   # "off" | "shadow" | "block"
def apply(name, mode, allowed, reason, signal_id) -> FilterResult
    # off    → allowed=True
    # shadow → אם allowed=False: log.warning("SHADOW %s would block %s: %s") ומחזיר allowed=True
    # block  → מחזיר כמו שהוא (reason נכתב ל-mt5_error)
```

### 4.2 משתני סביבה (ב־`.env` + `.env.example`)
```
H1_EMA_MODE=block                 # קיים; היום לא מוגדר → shadow
FILTER_NY_MIDDAY_MODE=shadow      NY_MIDDAY_START=12:00  NY_MIDDAY_END=14:00
FILTER_ONE_PER_BAR_MODE=shadow
FILTER_MIN_RR_MODE=off            MIN_RR=1.0
```

### 4.3 שינוי ב־`bot.py` — context
היום: `run_filters(trade, active_filters())` בלי context.
צריך:
```python
ctx = {
    "now": parse_ts(trade["created_at"]) or utcnow(),   # זמן האיתות
    "same_bar_open": same_bar_open(db, trade),          # ל־F
}
filt = run_filters(trade, active_filters(), context=ctx)
```
`same_bar_open(db, trade)`: ‏`select count(*) from gold_trades where entry_time = <trade.entry_time> and direction = <trade.direction> and mt5_ticket is not null and id <> <trade.id>`, ומחזיר `> 0`. שאילתה אחת לכל איתות, לא בכל poll.

### 4.4 סדר השרשרת ב־`active_filters()`
```
IsraelHours, LondonAfterNy, UsHolidayNextDay, NyOpen,   # קיימים
NyMidday (E), MinRR (G),                                 # בלי MT5, בלי DB
OnePerBar (F),                                           # מ־context (DB)
H1EmaSide                                                # עם MT5
```
במצב shadow כל הפילטרים רצים ונרשמים ביומן. במצב block השרשרת נעצרת בדחייה הראשונה, כמו היום.

### 4.5 כללים לכל פילטר
- **Fail-open:** כל חריגה או חוסר נתונים → `allowed=True` + `log.warning`. אף פעם לא חוסמים בגלל תקלה.
- `reason` קצר ומספרי, למשל: `ny_midday 12:35 NY in [12:00,14:00)` או `one_per_bar long @2026-11-12T14:05Z already open`.
- בלי `import` של Supabase בתוך הפילטרים. נתונים מה־DB מגיעים רק דרך `context`.

## 9. תיקוני לוגיקה בבוט (נוסף 2026-11-15)

### 9.1 נעילה על נר האיתות — `lock.py`, מצב `none`
**הבעיה:** בבדיקה הראשונה אחרי הפתיחה, `bars[-2]` הוא נר האיתות עצמו, הנר שה־Pine נכנס בסגירה שלו. אם הפתיל שלו נגע ב־40%, הבוט עובר ל־`pend`, למרות שב־Pine הנעילה נבדקת רק מהנר שאחרי הכניסה. בשבוע 09–13/11 זה קרה ב־4 עסקאות, שהסתכמו ב־‎−$249.
**התיקון:**
- `signal_bar_open = entry_time` (UTC). להמיר לשעון השרת עם `mt5.server_utc_offset()`, כי `bar["time"]` של MT5 הוא בשעון השרת.
- לבדוק 40% רק אם `closed_time_server > signal_bar_open_server`, כלומר הנר הסגור התחיל אחרי נר האיתות.
- אחרת: `return trade` בלי שינוי.

### 9.2 נעילה שנתקעת ב־`pend` — `lock.py`, מצב `pend`
**הבעיה:** בתחילת הנר הבא, אם `lock_sl` כבר בצד הלא נכון של המחיר (לונג: `lock_sl ≥ bid`, שורט: `lock_sl ≤ ask`), הבוט רושם ביומן "retry next poll" וממשיך לנסות כל 5 שניות. בינתיים הסטופ המקורי נשאר, והעסקה יכולה לחטוף הפסד מלא. ב־Pine, במצב כזה, היציאה בפתיחת הנר קורית מיד, קרוב לרמת ה־35%. בשבוע 09–13/11 נתקעו כך 4 עסקאות, ‎−$200.
**התיקון:**
- בבדיקה הראשונה של מצב `pend` אחרי שהנר הבא נפתח, אם `lock_sl` בצד הלא נכון: לסגור במחיר שוק עם `mt5.close_position(ticket)`.
- לרשום `lock_state="locked"` ו־`mt5_error="lock wrong side → market close"`.
- `resolve_exit_reason` יחזיר `lock`.
- בלי לולאת retry. אם הסגירה נכשלה, לנסות שוב בבדיקה הבאה, עד 3 ניסיונות, ואז לרשום שגיאה.
- את מקרה `gap < min_dist` (קרוב מדי לפי כללי הברוקר) משאירים כמו שהוא, עם retry.
- Env: ‏`LOCK_WRONG_SIDE=close` (ברירת מחדל) או `retry` (ההתנהגות הקיימת).

### 9.3 איתות שנחסם נבדק שוב ושוב — `bot.py`, `open_signal`
**הבעיה:** `fetch_new_signals` מחזיר כל שורה עם `status=open` ו־`mt5_ticket IS NULL`. איתות שנחסם בגלל פילטר, `max_open`, `slip` או `stops` נבדק שוב כל 5 שניות, עד שעוברות 180 שניות. לכן הוא יכול להיפתח באיחור. למשל, איתות שנחסם ב־14:29 יכול להיפתח ב־14:30 כשחלון החסימה נגמר, או כשמתפנה מקום פתוח.
**התיקון:**
- לבדוק את הפילטרים לפי זמן האיתות ולא לפי השעה הנוכחית: `context={"now": parse_ts(trade["created_at"])}`.
- כל חסימה סופית מסמנת את האיתות כמטופל: `copied_at=now`, ‏`mt5_error=<reason>`, ‏`mt5_ticket` נשאר NULL.
- ב־`fetch_new_signals` להוסיף `.is_("copied_at","null")`.
- חסימה בגלל `slip` או `max_open` נשארת זמנית, עם retry עד `MAX_AGE_SEC` כמו היום, אבל זה צריך להיות מוגדר במפורש: ‏`RETRY_ON=slip,max_open`.
- **הערה:** חלון ה־retry צריך להתחיל מ־`created_at`. ככה זה כבר עובד היום.

### 9.4 קטנים
- `lock_pend_bar_time` נשמר כשעון שרת אבל מסומן כ־UTC, ולכן הוא מוסט בשעתיים. צריך להמיר עם `server_utc_offset` לפני השמירה. ההשוואות הפנימיות יכולות להישאר בשעון השרת.
- `israel_hours`, ‏`ny_open` ו־`london_after_ny` מוגדרים בשעון ישראל. בשבועות שבהם מעבר השעון בישראל ובארה״ב לא באותו יום, החלונות זזים בשעה ביחס לניו יורק. כדאי להגדיר אותם בשעון `America/New_York` (למשל `ny_open` = ‏08:20–08:30 NY).
- לוודא ש־VPS מריץ את אותו commit כמו המחשב המקומי. הקומיט האחרון הוא 493f4d6 מ־21/09, ו־`h1_ema_side.py` עוד לא נדחף.
